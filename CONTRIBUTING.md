# CONTRIBUTING.md  
Guide de contribution au projet HuggingFace‑CATAR  
Version 1.0 — Participation, validation et reconnaissance

---

## 01 — Principes généraux

Le projet HuggingFace‑CATAR est ouvert à la communauté.  
Chaque contributeur peut participer à son évolution en respectant les invariants conceptuels et la logique du Passage CATAR.  

Les contributions doivent rester :  
- **documentées**,  
- **modulaires**,  
- **compatibles** avec l’architecture,  
- **transmissibles** à long terme.

---

## 02 — Types de contributions acceptées

- **Code** : amélioration du miner, du validator, des scripts, des tests.  
- **Documentation** : corrections, ajouts de guides, traductions.  
- **Concepts** : propositions sur le Corpus, invariants, Passage CATAR.  
- **Interfaces** : développement d’outils CLI, API, ou interface web.  
- **Communauté** : organisation de discussions, propositions de roadmap, gouvernance ouverte.

---

## 03 — Processus de contribution

1. **Forker le dépôt** HuggingFace‑CATAR.  
2. **Créer une branche** dédiée à votre contribution (`feature/nom`, `fix/nom`).  
3. **Documenter vos changements** dans un README ou un commentaire clair.  
4. **Ajouter des tests** si la contribution touche au code.  
5. **Soumettre une Pull Request** (PR) vers la branche principale.  

Chaque PR doit inclure :  
- justification,  
- impact attendu,  
- compatibilité avec les modules existants,  
- plan de test ou validation.

---

## 04 — Validation des contributions

Les contributions sont validées selon :  
- **Cohérence conceptuelle** : respect du Corpus et du Passage.  
- **Neutralité cognitive** : absence de biais ou dérives.  
- **Qualité technique** : code lisible, testé, reproductible.  
- **Documentation** : explication claire et transmissible.  

La validation est communautaire : revue par les mainteneurs et discussions ouvertes.

---

## 05 — Reconnaissance des contributeurs

Les contributeurs sont reconnus par :  
- mention dans le fichier `CONTRIBUTORS.md` (à venir),  
- attribution académique ou communautaire,  
- possibilité de rejoindre la gouvernance ouverte du projet.  

---

## 06 — Règles de gouvernance

- Aucune contribution ne doit altérer les invariants conceptuels (Moije / Soije, Absolu / Relatif, Passage CATAR).  
- Les modules doivent rester indépendants et améliorables sans casser les autres.  
- Les décisions majeures (roadmap, architecture) doivent être discutées publiquement via Issues ou Discussions GitHub.  

---

## 07 — Code de conduite

Les contributeurs doivent :  
- respecter les autres participants,  
- rester neutres et constructifs,  
- éviter les dérives (domination, manipulation, élitisme),  
- favoriser la transmissibilité et la pérennité du projet.  

---

## 08 — Vision long terme

Le projet HuggingFace‑CATAR est conçu pour évoluer vers :  
- une gouvernance communautaire ouverte,  
- une DAO ou une fondation,  
- une standardisation académique et internationale.  

Chaque contribution participe à cette continuité.
